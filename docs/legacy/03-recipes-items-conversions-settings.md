# Legacy behavior 03 — Recipes, ingredients, conversions, yields, settings
Line numbers: `legacy/app.html`.

## 1. Recipe object
`newRecipe` (2899): `{id, code, name:'New Recipe', cat:'', brandId:S.activeBrand, status:'draft', history:[], type:'menu'|'sub', output:1, subQty:0, subUom:'Gram', batchOut:0, batchUom:'Gram', price:0, photo:'', lines:[{code:'',qty:0,unit:'Gram',y:1}], method:['']}`. Optional: `lockedBy` (string "approved by"), `lockedAt` (ISO), `buffer` (fraction; all seed cards 0.15), line `yp` (percent, set only by the editor's "Yield %" column). Legacy `r.brand` (name) migrated to `brandId` then deleted. A sub-recipe keeps `subQty/subUom` in sync with `batchOut/batchUom`; unit cost = total/(batchOut||subQty). Line units offered: Gram, Ml, Each, Slice (3254); `batchUom`: Gram, Ml, Each.
**Two yield concepts:** `y` (divisor; valid 0<y≤10 else treated as 1; all 1 after the yield migration) and `yp` (waste %; the editor's "Yield %" column edits `yp` clamped 0–99 via `setYieldPct` 3488). Print card (6031) and exports (5359, 4507) show `y*100`, import (5625) sets `y` via `rYield` (blank→1; >1.5 → /100; capped 1) and never `yp`/`buffer`; **legacy round trip loses `yp`/`buffer`** → D-17 adds `Waste %` and `Card buffer` columns (older files without them leave values untouched).

## 2. IDs and codes
`uid()` ids (non-deterministic) – not migrated. `nextCode(type,brandId)` (2871): `<brand.code or 'GEN'>-<SR|MN>-<4 digits>`, smallest unused number (fills gaps), uniqueness case-insensitive across all cards; `isAutoCode` regex `^[A-Z]{2,4}-(MN|SR)-\d{4}$` (i). Auto-codes regenerate when brand (`setBrand` 3468) or type (`setF` 3484) changes, and via ↻ `regenCode` (2880). Hand-typed codes were unvalidated in legacy (no uppercase, no uniqueness). **New (D-12/D-33):** unique case-insensitively among non-deleted recipes; cross-namespace collision with ingredient codes rejected; rename cascades to referencing lines/menu cells in one transaction; import uppercases codes (as legacy 5604).

## 3. Lock / unlock / history
Status: `draft` | `locked`. Permissions: lock = `recipe.lock` (gm, cc, chef); unlock = `recipe.unlock` (gm, cc); delete = `recipe.delete` (gm, cc); deleting a locked card also needs `recipe.unlock`.
- **Lock** (`lockRecipe` 3003, `doLock` 3027): modal shows food cost, FC%, sales price, net profit, warnings for cost error / missing sales price on a menu card; "Approved by" free text required (default `CUR.name`); sets `status='locked'`, `lockedBy`, `lockedAt`; history `{a:'Locked and approved', w:who, t}`; audit `Locked card` = `code – name (approved by X)`. **New (D-29/D-26):** refuse while any line has null price or missing conversion unless a GM overrides with a reason; store `costAtLock` snapshot.
- **Unlock** (3037): `status='draft'`, delete `lockedBy/lockedAt`; history `{a:'Unlocked for editing', w}`; audit `Unlocked card`. (Legacy PIN gate removed.)
- `logHist` keeps newest-first, cap 40 per card. Only lock/unlock write history.
- Locked cards: `vEdit` routes to read-only `vLocked` (3666) = `buildCardHTML` + Approval History table; buttons: All cards, Duplicate as draft, Print, Unlock to edit. Setters guard via `editable()` (3435): "approved and locked – unlock it first". Import never overwrites locked cards (skipped, action `locked`). Latent gap: `setYieldPct, applyCode, pick, commitCode, addFromBrowse, regenCode` don't call `editable()` — server must block all edits of locked cards.
- Bulk: `bulkLock` (3053; `doBulkLock` 3066 **crashes** at 3074 referencing `trash` → nothing saved) → implement intended behavior (D-18): lock selected, history each, one audit entry. `bulkUnlock` (3077) one audit `Unlocked cards` "N cards".

## 4. Editor rules
Almost no validation: no required name/code; `output` min 1 in UI, cost uses `max(1, …)`; `qty` num; Yield % clamp 0–99. Ingredient picker (`matches` 3516): all sub-recipe cards with a code from any brand + `S.items` filtered by `itemFor(item, activeBrand)`; autocomplete up to 30, "Search raw materials" up to 60. `commitCode` (3586) resolves typed text: exact code → case-insensitive code → unique exact name → single fuzzy match; else toast "Several items match…/No ingredient matches"; blank clears the line. `applyCode` (3568) sets unit from item UOM if in {Gram,Ml,Each,Slice} and `y=1` if zero. `delLine` always leaves ≥1 blank line. Method is `string[]`; import splits a cell on `|`.
No cycle prevention (new rule D-13 blocks). Menu-type code as a line → cost error "not a sub-recipe".

## 5. Delete / duplicate / photos
- `delRecipe` (2914): checks lock rule; `confirmDelete` (2922) needs `recipe.delete`, lists surviving cards that reference the code (warn only). `doDelete` (2963): moves to in-memory single-batch `trash`, appends uppercased codes to `S.deletedCards`, audit `Deleted card(s)`, UNDO toast; `undoDelete` (2989) restores, audit `Restored card(s)`. **New (D-14):** soft delete `deletedAt`, restore re-checks code collision.
- `dupRecipe` (2906): needs `recipe.create`; deep copy incl. photo/lines/method/buffer/yp; new id; `code=nextCode`; name `+ ' (copy)'`; draft; history []; lock fields cleared; audit `Duplicated card` "old → new".
- Photos: `readPhoto` (1314) rejects non-images, scales to max 760px side, white background, JPEG q 0.72 → data URL in `r.photo`; audit `Added a dish photo` (code · WxH · KB) / `Removed the dish photo`. Backup warns >4000 KB total. **New (D-37):** keep downscale (~300 KB target, 1 MB hard cap) in browser; store in `RecipePhoto` table; never select in lists.
- New card requires an active brand (modal brand picker); **D-27:** brand required, no brandless cards.
- List (`vRecipes` 2752): filters `rq` (name+code+cat+brandName), `rbrand`, `rstatus`, `rcat` chips; page size 50 (`RPAGE` 2737); category chip counts computed after brand/status filters but before category/search; category order: Chicken, Lamb, Veal, Beef, Fish, Main Course, Breakfast, Soup first, then alphabetical; brand filter select overrides active workspace; "— no brand —" option (now obsolete).
- Legacy audits for recipes: price change (`Changed sales price` code: old → new, 3480), yield change (`Changed a line yield`), photo, duplicate, delete/restore, lock/unlock. **New (D-15):** also recipe create and edit.

## 6. Items (`vItems` 3730)
Filters: text on code+name, brand (all / `__shared` / specific), `sub` category; page size 60. Columns: code, name (+flag text), UOM, price (6dp, red "missing" pill when null), Available To (Shared pill or brand code pills), sub category, Status (review if flagged else ok). Edit form: code (readonly when editing), name, UOM select, price (empty → null), cat, sub, Shared checkbox + per-brand checkboxes, review flag. `saveItem` (3830) rebuilds the object (drops unknown fields); validation only: code required, unique on new (exact, case-sensitive); negative price passes (new: reject negatives). Price-change detected `num(was)!==num(new)`; audit `Changed purchase price` (`CODE name: old → new`, 6dp), `Edited ingredient` (code), `Added ingredient` (`code name`), `Deleted ingredient` (code). Delete needs `items.edit`, blocked if any recipe line has that exact code ("Used by N card(s)"); legacy leaves the orphan `conv` key (new: delete conversion too). Item import (4660–4830): columns code/name/uom/price/cat/sub via header map; rejects unknown unit (IUOM map), unparsable/negative price, blank code or code starting `EXAMPLE`; last duplicate wins; blank price keeps old; new items cat/sub 'Uncategorised'; brand choice with grant extends brand-scoped items; dry-run then commit; audit `Uploaded price list`. **New (D-26):** every price change appends `IngredientPriceHistory`; imports flag large variances.

## 7. Conversions (`vConv` 3887, `saveConv` 4031)
`S.conv[code]=[recipeUnit, factor]` = recipe units per 1 purchase unit; editor accepts either direction (`p2r`/`r2p`) and stores the reciprocal. CONV_UNITS Gram/Ml/Each/Slice. Save validation: item code required and must exist, number >0, unit must differ from item UOM; direction sanity warnings non-blocking. Orphan keys shown as "check". Audit `Set unit conversion` ("code: 1 PU = factor RU"), `Removed unit conversion`. Permission `conv.edit`.

## 8. Yields (`vYields` 4068)
`YIELD_REF` static (43 rows `[category,item,fraction,note]`, 8 categories), read-only, search + % display, **not used by costing**. Stays static data (no table, no CRUD).

## 9. Settings (`vSettings` 4085)
Percent fields pkg, del, lab, ops, buffer, target, vat: number input step 0.01, stored `num(v)/100`, no min/max in legacy (new: validate sensible range, e.g. 0–100 for loads, audit old→new + count of cards affected); `currency`, `priceDate` free text (new: `priceDate` as date). Permission `settings.edit` (gm, fin) — legacy enforced only via `data-perm`, new server-side. Brand management lives here: `addBrandS` (4187; name required, code A–Z0–9 max 4, defaults first 3 letters + XXX, unique name (ci) and code, colour `#BB5E1E`, id `'b'+Date.now().toString(36)`), `doEditBrand` (4258; name+code required, unique code only; doesn't touch nameAr/locs; **changing code doesn't renumber card codes**), `delBrand` (4268; `brands.edit` GM; blocked if recipes belong to it; audit `Removed brand`). Logo upload `pickLogo` (4235): PNG/JPEG/SVG/WebP ≤3 MB, canvas to 320px wide PNG (keep original if smaller), saved with brand. Legacy had no audit/guard on brand add/edit → new (D-15/D-16) audited and `brands.edit`.
